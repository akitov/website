# Blog posts

Drop a new `.md` file in this folder to publish a post. Filename = URL slug.

## Frontmatter

```yaml
---
title: Post title              # required (omit for type=quote)
subtitle: Short summary        # shown on the homepage card
updated: 21.03.2013            # DD.MM.YYYY — used for sort + display
type: lesson                   # quote | lesson | event
category: Life                 # category pill
images:                        # optional gallery; first item = hero image
  - /blog/images/hero.jpg
  - /blog/images/inline.jpg
quote: "..."                   # required for type=quote
author: Author name            # required for type=quote
source: Source URL             # optional for type=quote
---

Markdown body goes here.
```

> Field aliases honored by the renderer (any of these works in place of
> `subtitle`): `slug`, `excerpt`. Other legacy aliases: `date` → `updated`,
> `image` → first entry of `images[]`. New posts should prefer the
> canonical names above, but mixing aliases is supported.

## How discovery works

1. `home.js` first reads `/blog/manifest.json` (generated by
   `scripts/regenerate.mjs`).
2. It also parses the Python `http.server` directory listing and unions
   the two — so brand-new `.md` files appear in dev without re-running
   the regenerate script.

The GitHub Action at the repo root (`.github/workflows/reindex.yml`)
re-runs the regenerate script on every push to
`artifacts/personal-site/blog/**`, so the deployed site always has a
fresh manifest plus per-slug pre-rendered pages at `/<slug>.html`.
